# Spec: Sessions — saved conversations the Owner can resume

Status: ready-for-agent

## Problem Statement

Everything the Owner says to Jarvis lives only in the open page: a reload or a closed tab loses the whole conversation. Because the Owner can't keep several conversations apart, every topic piles into one long stream. Jarvis gets loaded with unrelated context, and the Owner can't go back to "the conversation about the trip" later.

## Solution

Every conversation becomes a saved Session. Opening Jarvis starts a new Session, which is saved once its first Turn completes and then gets its own URL, so reloading stays in it. A "Sesiones" group in the sidebar lists Sessions by last activity, newest first, loading more as the Owner scrolls. Each item shows its Session Title (generated by Jarvis after the first Turn) and a relative date. The Owner can start a new Session, resume any earlier one, or delete one after confirming. The server owns the Transcript, and Jarvis sees only the most recent Turns of the current Session.

## User Stories

### Saving and resuming

1. As the Owner, I want my conversation to be saved as I talk, so that a reload or a closed tab doesn't lose it.
2. As the Owner, I want reloading the page to keep me in the Session I was in, so that I can pick up where I left off.
3. As the Owner, I want opening Jarvis fresh to start a new Session, so that each topic gets its own conversation.
4. As the Owner, I want a Session to be saved only once its first Turn is done, so that the list never fills with empty Sessions.
5. As the Owner, I want a resumed Session to show its full Transcript, so that I can see what we already said.
6. As the Owner, I want Jarvis to remember what was said earlier in the current Session, so that follow-ups like "¿y mañana?" still work after a reload.
7. As the Owner, I want inline errors ("No pude transcribir…") to stay out of the saved Session, so that a resumed Session shows only real Turns.
8. As the Owner, I want spoken and typed Turns to be saved the same way, so that it doesn't matter how I talked to Jarvis.
9. As the Owner, I want a Session's link to show a clear "no existe" state if the Session was deleted, so that an old link doesn't break the page.

### The Session list

10. As the Owner, I want a "Sesiones" group in the sidebar, so that I can see my conversations from any page.
11. As the Owner, I want Sessions ordered by last activity, so that the one I just resumed is at the top.
12. As the Owner, I want each Session to show its Session Title and how long ago it was active ("hace 2 días"), so that I can find the one I want.
13. As the Owner, I want the list to load more Sessions as I scroll, so that a long history doesn't slow the sidebar down.
14. As the Owner, I want the current Session highlighted in the list, so that I know where I am.
15. As the Owner, I want the "Jarvis" page link to stay highlighted while I'm in any Session, so that the navigation stays honest.
16. As the Owner, I want a "Nueva sesión" button, so that I can start a new topic in one click.
17. As the Owner, I want clicking a Session to open it on the Jarvis page, so that I can resume it right away.
18. As the Owner, I want a new Session to appear at the top of the list as soon as its first Turn is done, so that the list stays current without a reload.
19. As the Owner on mobile, I want the sidebar to close when I open a Session, so that I land straight in the conversation.

### Session Titles

20. As the Owner, I want Jarvis to give each Session a short Spanish title after its first Turn, so that I can recognise it in the list.
21. As the Owner, I want generating the title never to slow down Jarvis's Reply, so that talking stays fast.
22. As the Owner, I want a Session whose title couldn't be generated to still show something sensible (its date), so that the list never has blank items.

### Deleting

23. As the Owner, I want a "⋯" menu on each Session with "Eliminar", so that I can remove conversations I don't need.
24. As the Owner, I want to confirm before a Session is deleted, so that I don't lose one by accident.
25. As the Owner, I want deletion to be permanent, so that what I deleted is really gone.
26. As the Owner, I want deleting the Session I'm in to take me to a new Session, so that I'm never left on a deleted one.

### Switching mid-Turn

27. As the Owner, I want switching Sessions while Jarvis is Speaking to stop the voice at once, so that I don't hear an old answer in a new conversation.
28. As the Owner, I want a Reply that was still Thinking when I switched to be saved in its original Session, so that nothing is lost.
29. As the Owner, I want the Session I switch to to open Idle, so that I can talk straight away.

### Unchanged behaviour

30. As the Owner, I want Widgets to stay as they are when I switch Sessions, so that the screen doesn't jump around.
31. As the Owner, I want Plugins, Widgets and weather to work exactly as before inside any Session, so that Sessions cost me nothing.

## Implementation Decisions

### Domain

- `CONTEXT.md` now defines a **Session** as saved and resumable, and adds **Session Title**. The client-side `createJarvisSession` keeps its name; it is now the live view of one Session.

### Shared database (prefactor)

- The SQLite database module currently lives under Plugins. It moves to a shared place with one schema and one migrations folder, used by Plugins, Sessions and (later) Memories. Same file and same env var. Plugins behaviour is unchanged.

### Sessions store (new, server, deep module)

- A factory over the shared database with an injected clock. Operations:
  - start a Session with its first Turn (returns the new id)
  - add a Turn to a Session (bumps its last activity)
  - the last N Turns for Jarvis (N = 20)
  - the full Transcript of a Session
  - one page of the list, ordered by last activity descending, with a cursor (20 per page)
  - set a Session's Session Title
  - delete a Session and its Turns
- Schema: a sessions table (id, title nullable, created at, last activity at) and a turns table (session id with cascade delete, position, the Owner's text, Jarvis's Reply text, created at). A Turn is saved only when Jarvis's Reply is ready, so a failed Turn saves nothing.
- Session ids are opaque and URL-safe.

### Reply contract

- The client no longer sends the Transcript. The Reply request carries an optional Session id and the Owner's new message, plus the Widget layout and coordinates as today.
- The server loads the last 20 Turns of the Session, generates the Reply, and saves the Turn. If there was no Session id, it creates the Session with this first Turn. The response adds the Session id.
- An unknown Session id is a client error. The client treats it as "this Session no longer exists".
- `Brain.reply` changes from taking all the lines to taking `{ sessionId?, text }`, and returns `{ sessionId, text, widgetChanges }`.

### Session Title

- After the first Turn is saved, the server asks the chat model for a short Spanish title (3 to 5 words) in a separate call that doesn't block the Reply. It is an injected function so tests never call the model. If it fails, the title stays empty and the list shows the date.

### Routes and client

- `/` is a new, unsaved Session. A Session lives at `/sessions/[id]`. After the first Turn the client replaces the URL with the Session's URL without remounting the page or interrupting Speaking.
- Opening `/sessions/[id]` loads that Session's Transcript into the Jarvis page. If the id doesn't exist, the page shows a short Spanish "Esta sesión ya no existe" state with a "Nueva sesión" action.
- The navigation helper treats `/` and `/sessions/*` as the Jarvis page.
- The client Session gets a way to load a saved Transcript and to be torn down. When the Owner switches Sessions, the old one stops the Voice and ignores its late callbacks (the existing generation guard). The server still saves the in-flight Turn to its original Session.

### Sidebar

- A "Sesiones" group below the page links, with a "Nueva sesión" button, the list with infinite scroll (load the next page when the end comes into view), the current Session highlighted, and a "⋯" menu per item with "Eliminar".
- "Eliminar" opens a confirm dialog. On confirm, the Session is hard-deleted and removed from the list, and if it was the current Session the Owner goes to `/`.
- The list refreshes its first page when a Session is created, titled or deleted.
- Listing, deleting and loading a Transcript are server endpoints or server actions next to the store. All UI text is in Spanish and uses the existing `@workspace/ui` components (sidebar, dropdown menu, alert dialog, skeleton).

## Testing Decisions

- Good tests use only the public interface and assert what the Owner or Jarvis would notice: which Turns are saved, which Turns Jarvis is given, list order and paging, what disappears after a delete, and what the Session shows. They don't assert on table shapes or call order.
- **Sessions store** (new seam): tested against an in-memory SQLite database with migrations applied (as the Plugins tests do) and a fake clock. Cover: starting with a first Turn; adding Turns bumps last activity; last-20 window; full Transcript order; paging by last activity with a cursor (including ties and the last page); setting a title; delete cascades its Turns; unknown ids.
- **Jarvis Session** (existing seam, extended): fake Brain now takes `{ sessionId?, text }`. Cover: the first Turn adopts the returned Session id and later Turns send it; errors are not sent or saved; loading a saved Transcript; tearing down while Speaking stops the Voice; a late Reply after teardown changes nothing on screen.
- **Navigation** (existing tests): `/sessions/abc` counts as the Jarvis page.
- Title generation, the sidebar, infinite scroll and the confirm dialog are checked by hand.
- Prior art: the Plugins tests (factory with in-memory store), the session tests (fake adapters and deferreds), and the navigation tests.

## Acceptance criteria

- Talking on `/`, then reloading, keeps the conversation and the URL is `/sessions/<id>`.
- Opening `/` again starts an empty Session, and the earlier one is in the "Sesiones" list with a generated title.
- Scrolling a long list loads more Sessions.
- Resuming an earlier Session shows its Transcript, and a follow-up question uses its context.
- Deleting a Session (after confirming) removes it for good. Deleting the current one lands on a new Session.
- Switching Sessions while Jarvis is Speaking stops the voice.

## Out of Scope

- Remembering anything across Sessions (the Memory spec).
- Renaming, pinning, archiving or searching Sessions.
- Creating, switching or deleting Sessions by voice.
- Summarizing older Turns. Jarvis sees only the last 20.
- Exporting or sharing a Session.
- Saving the audio of Utterances or Replies.
- Per-Session Widget layouts.
- Syncing across devices (everything lives in the local database).

## Further Notes

- Sessions are a prerequisite for the Memory spec: a Memory can point at the Session it was learned in.
- Turns are saved only after a successful Reply, so Owner text that got no Reply (e.g. the model failed) is lost on reload. This is acceptable for now.
